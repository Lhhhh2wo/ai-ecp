## 二、系统简介

本系统是一个支持**智能客服**、**智能选品**、**智能组货**三项 AI 能力的电商在线售货网站系统，具备两个区别于通用电商系统的核心特征：

### 1. 品类自定义（JSON 驱动）

商品品类结构由用户（商家）以 JSON 文本自定义，系统在分钟级完成「语法校验 → 结构语义校验 → 品类树构建 → 衍生能力生成 → 落库发布」五步处理，自动产出：

- 属性 Schema（必填 / 可筛选 / 可检索 / 取值范围）
- 动态商品发布表单（无需为新增品类开发页面）
- 检索与筛选索引映射
- AI 提示词中的品类上下文片段

新增品类**无需代码变更与系统发版**。

### 2. AI 能力内建（能力中台）

三项 AI 能力以中台组件形式内建，共享大模型网关、向量检索、提示词管理、工具注册与安全护栏：

| 能力 | 核心设计 |
|---|---|
| 智能客服 | 意图分流：知识咨询走 RAG 检索增强生成，业务事实走受控工具调用；答复经安全护栏过滤后流式返回，置信度不足时携带会话摘要转接人工 |
| 智能选品 | 画像构建 → 多路并行召回 → 精排打分 → 业务规则过滤 → 多样性重排 → 冷启动兜底；行为埋点回流形成自增强闭环 |
| 智能组货 | 大模型只负责生成搭配理由，候选商品的库存、履约、价格与毛利全部由业务服务计算校验；四维同时成立的组合才输出，否则降级为单品推荐 |

## 四、使用说明

### 4.1 浏览静态网站

- **线上访问**：直接打开 <https://ai-ecp-uml-design.app.workbuddy.host/>，手机可用相机或微信「扫一扫」扫描 `站点访问二维码.png`。
- **离线访问**：进入 `05-静态网站/`，用浏览器打开 `index.html` 即可。全站无外部依赖，断网可用。
- **图集查看器**：在「UML 图集」页点击任意图，可进入全屏查看器，支持滚轮缩放、拖动平移、手机双指捏合、`+`/`-`/`0`/`1` 快捷键与矢量图下载。

### 4.2 修改并重新渲染 UML 图

```bash
# 1. 编辑 UML 源文件（位于 06-工具脚本 同级的图定义文件，或直接编辑 .puml）
# 2. 渲染单个图（需 Java 8+）
java -jar plantuml.jar -charset UTF-8 -tsvg -o ../dist src/03-01_uc_overall.puml

# 3. 批量渲染全部图（SVG + 200DPI PNG）
python tools/render_uml.py

# 4. 重新生成图源（修改 tools/uml_defs_a.py、uml_defs_b.py 中的定义后执行）
python tools/gen_puml.py
```

### 4.3 重新构建报告与站点

```bash
python tools/build_docs.py    # 由正文 HTML 生成两份 Word 报告
python tools/build_site.py    # 重建静态站点
python tools/make_qrcode.py "<站点地址>"   # 重新生成访问二维码
```

### 4.4 图源文件的独立渲染

每个 `.puml` 文件均为**自包含**文件：已内联完整的样式声明（严格 UML 2.x 黑白风格、微软雅黑中文字体），可直接用任意 PlantUML 工具（本地 JAR、VS Code 插件、IDE 插件）独立渲染，无需任何外部依赖。

## 五、后续开发建议

1. **从图到码**：以图 4-1 的分层包结构建立工程骨架，以图 4-2 / 4-3 的类结构生成 Java 接口与抽象类骨架。
2. **优先实现品类引擎**：图 3-6 与图 4-9 已完整定义 JSON 解析链路，可作为第一个可验证的端到端能力（需求编号 FR-07 ~ FR-10）。
3. **AI 能力先落地契约**：先实现 `ILlmGateway`、`IVectorSearch`、`IAiCapability` 三个接口及其实验性实现，再逐步替换为生产级模型服务。
4. **严守降级契约**：所有 AI 接口响应必须携带 `degraded` / `degradeReason` 字段，确保 AI 异常不影响交易主流程（非功能需求 NFR-06、NFR-07）。
5. **品类规范的版本管理**：品类 JSON 规范（报告 3.6 节）新增字段时，必须评估对历史数据的影响，解析器对未知字段采取「忽略并告警」策略。
